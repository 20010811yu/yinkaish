# 修复：YK-6A 参数乱码（历史测试数据污染）

## 根因（已审计确认）
之前做「参数组保存回读」测试时，通过控制台内联中文发出的 PUT 被 Windows 控制台编码污染，把 YK-6A（product_id=1）的参数整体覆盖成了乱码（当时回读输出已乱但未被抓住）。全库审计确认：**仅此 2 行参数损坏**，news/honors/jobs/partners/products 其余数据全部干净。

## 修复方式（零控制台编码参与）
1. 从 `server/sql/seed.sql` 提取 YK-6A 的 16 行参数种子（awk 按行提取，UTF-8 文件直读直写）
2. 生成恢复 SQL 文件（`SET NAMES utf8mb4` + `DELETE FROM product_params WHERE product_id=1` + 种子 INSERT），用 mysql 客户端 `--default-character-set=utf8mb4` 执行
3. API 回读核对 16 行参数与种子一致

## 验证与收尾
1. 浏览器打开 YK-6A 参数弹框确认显示正常；前台产品页参数无回归
2. 复跑乱码审计（五接口全绿）
3. errorlog 记 ERR-014（控制台内联中文写库被编码污染——教训：凡涉及中文数据的写库操作必须走 UTF-8 文件，禁止控制台内联）；提交推送（恢复脚本为一次性操作不留仓库文件）
