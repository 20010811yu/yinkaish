# 管理端安全加固方案

后端为 `server/`（Express + MySQL），已有：JWT（12h）+ bcrypt + `requireAdmin` 中间件（每请求校验 `admins.is_active`）+ 上传 mimetype 白名单/服务端重命名/5MB 限制 + 参数化 SQL。本次加固以下缺口，全部在后端 + 少量配置：

## P0（必须修的洞）

1. **JWT 密钥硬回退**（`server/src/middleware/auth.js`）
   - 生产环境（`NODE_ENV=production`）若 `JWT_SECRET` 未设置则直接抛错拒绝启动，杜绝可伪造 token。

2. **CORS 全开**（`server/src/index.js`）
   - `app.use(cors())` 改为白名单：只允许 `FRONTEND_ORIGIN` 环境变量指定的源（.env 配置，支持逗号分隔多个）；开发模式默认放行 localhost。

3. **登录限速防爆破**（`server/src/routes/admin/auth.js`）
   - `express-rate-limit`：`/api/admin/login` 每 IP 15 分钟 5 次，超出返回 429；登录失败信息统一为「用户名或密码错误」，不区分用户名是否存在。
   - 全局 API 加宽松限速（如每 IP 每分钟 120 次），上传接口单独更严格（每 15 分钟 30 次）。

## P1（重要加固）

4. **安全响应头**：引入 `helmet`（含 CSP 可放宽为适合本站的形式，img-src 放行 `data:` 与自托管）。

5. **输入值校验**（`server/src/routes/admin/content.js` 的 crud 工厂）
   - 字段名白名单已有，补值类型校验：字符串长度上限（如 5000，富文本字段放宽至 200KB）、数字字段必须是数字、拒绝未知类型，超限返回 400。

6. **富文本 XSS 消毒**
   - 新闻等富文本入库前用 `sanitize-html`（白名单标签/属性，去 script/事件）消毒，防止存储型 XSS。

## P2（顺手补齐）

7. **密码策略**：改密/登录接口强制 ≥8 位且含字母和数字（`server/src/routes/admin/auth.js`）。

8. **部署配置**：`netlify.toml` 前端侧补安全头（X-Frame-Options 等）；.env.example 补 `JWT_SECRET`、`FRONTEND_ORIGIN` 说明；README/交付说明提醒 API 必须走 HTTPS。

## 明确不做（记录原因）
- 不迁移 httpOnly cookie（改动大，当前 Bearer + 401 自动登出已够用，富文本消毒后 localStorage 存 token 风险可控）。
- 不加账号锁定/审计表（需 DB 迁移，先用 IP 限速覆盖主要风险）。
- 滑块验证码保留现状（仅前端体验项，不作为安全边界）。

## 验证
- `cd server && npm run build`/启动自检：无 JWT_SECRET 时生产模式拒绝启动。
- 手测：错误Origin 被拒、登录第 6 次 429、超长字段 400、富文本含 `<script>` 被剥离。
- 前端 `npm run build` 通过。
